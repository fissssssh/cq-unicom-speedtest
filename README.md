## 测速来源

基于**重庆联通官方测速平台**([cesu.cqwin.com](http://cesu.cqwin.com))的真实测速服务实现:

- 复用官方测速节点与 1GiB 随机数据流,测速结果与官方页面口径一致
- 测速节点**动态获取**,官方调整节点时自动跟随(失败回退内置列表)
- 签约带宽、提速带宽、所属区域等宽带信息来自官方接口,自动用于结果对比
- 协议细节通过对 Chrome 抓包与官方前端脚本分析得出

## 功能特性

- ✅ 签约带宽自动获取(500M/1000M 等),实测速率与签约带宽**达成率对比**
- ✅ 测速节点**动态获取**(官方接口),失败自动回退内置列表
- ✅ 8 个节点延迟测试,自动选择**延迟最低**的节点测速
- ✅ 多连接并发下载(官方做法,默认 4 并发)
- ✅ 实时进度条:按时间推进,显示瞬时/平均速率、已传字节
- ✅ 多轮测速取最大值(默认 3 轮),结果含最大/平均速率与带宽档位参考
- ✅ 支持手动指定签约带宽、服务器、时长、轮数、并发数
- ✅ 深色终端优化界面(自动检测终端颜色能力:真彩色 → 256 色 → 16 色;`NO_COLOR=1` 可禁用颜色)
- ✅ 跨平台:Linux / Windows(Git Bash、WSL)均可运行

## 使用方法

```bash
# 赋予执行权限(仅 Linux/macOS)
chmod +x cq-unicom-speedtest.sh

# 基本测速(默认:12 秒 × 3 轮 × 4 并发)
./cq-unicom-speedtest.sh
```

### 参数说明

| 参数 | 说明 | 默认值 |
|---|---|---|
| `-t <秒>` | 每轮下载测速时长(官方单次 15 秒) | 12 |
| `-n <轮数>` | 测速轮数,取最大值作为结果 | 3 |
| `-c <并发>` | 并发连接数(官方 10 并发) | 4 |
| `-b <兆>` | 手动指定签约带宽(Mbps),用于达成率对比 | 自动从接口获取 |
| `-s <IP>` | 手动指定测速服务器,跳过延迟选择 | 自动选择最低延迟 |
| `-p` | 只测各节点延迟,不进行下载测速 | - |
| `-h` | 显示帮助 | - |

### 使用示例

```bash
./cq-unicom-speedtest.sh                     # 基本测速
./cq-unicom-speedtest.sh -t 15 -n 5          # 每次 15 秒,共 5 轮(更准确)
./cq-unicom-speedtest.sh -c 8                # 8 连接并发(千兆宽带推荐)
./cq-unicom-speedtest.sh -b 1000             # 手动指定签约带宽 1000M
./cq-unicom-speedtest.sh -s 221.13.126.6     # 指定测速服务器
./cq-unicom-speedtest.sh -p                  # 只测延迟
```

**结果解读**:

- 速率单位 `Mbps` = 兆比特/秒(运营商宣传口径);`MB/s` = 兆字节/秒(1 MB/s = 8 Mbps)
- **达成率** = 最大下行速率 ÷ 签约带宽:≥95% 绿色「达标」,≥80% 黄色「基本达标」,<80% 红色「差距较大」
- 超过 100% 属正常现象(运营商通常留有余量,如千兆宽带可测出 1400 Mbps)

## 常见问题

**Q: 提示"未能获取签约带宽"**
非重庆联通宽带环境(或接口临时异常)时无法自动获取,可用 `-b <兆>` 手动指定。

**Q: 提示"官方节点获取失败,回退内置列表"**
官方接口临时不可用时自动使用内置的 8 个节点,不影响测速。

**Q: 实时进度条不显示**
进度条仅在输出到终端时启用;重定向到文件/管道时自动禁用,属正常行为。

**Q: Windows 下如何运行**
安装 [Git for Windows](https://gitforwindows.org/),在 Git Bash 中执行 `./cq-unicom-speedtest.sh` 即可。

**Q: 测速会消耗多少流量**
每轮每连接最多下载 1GiB,默认 4 并发 × 3 轮,理论峰值约 12GiB(实际按链路速率和时长决定,如 1000M 宽带 12 秒约 2GB/轮)。可用 `-t` 缩短时长、`-c` 降低并发减少流量。
